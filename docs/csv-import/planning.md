## Description

為「全家人記帳系統」新增「匯入 CSV」功能，讓使用者能將外部 CSV 檔案中的收支記錄匯入至指定帳本。支援批次匯入，自動驗證每筆記錄的格式與權限，錯誤記錄會跳過並顯示錯誤訊息，不影響其他記錄的正常匯入。

範圍限於單一帳本的 CSV 匯入；不新增資料庫表，僅寫入既有 `entries` 表；CSV 檔案上傳後即時處理，不儲存在伺服器。

## User Story

- 作為家庭成員，我希望能把舊記帳軟體匯出的 CSV 檔案匯入到此系統，避免歷史記錄遺失。
- 作為家庭成員，我希望能批次匯入多筆收支記錄，而不需要一筆一筆手動輸入。

## To Reproduce

本項目非錯誤（bug）類需求，不適用重現步驟。

## Expected behavior

### 匯入 CSV 功能
- 使用者在帳本詳情頁點擊「匯入 CSV」按鈕
- 系統顯示匯入頁面，包含 CSV 檔案上傳欄位
- 使用者選擇 CSV 檔案後提交，系統進行驗證與匯入
- 每筆記錄獨立驗證：日期格式、類型（收入/支出/轉帳）、金額格式、分類長度
- 錯誤記錄不中斷整體匯入，錯誤訊息顯示在結果頁面
- 匯入完成後顯示結果摘要：成功筆數、失敗筆數、失敗原因

### 權限檢查
- 所有查詢與寫入皆透過 `ledger_access` 做 IDOR 防護，使用者只能匯入其被授權帳本的記錄
- viewer 僅可檢視，owner/member 可匯入（匯入為寫入操作，僅 owner/member 可執行）

### 檔案格式
- CSV 檔案編碼：UTF-8（含 BOM 或不含 BOM 均可，BOM 會自動去除）
- 欄位順序：日期、類型、金額、分類、記錄者、備註
- 日期格式：Y-m-d（例如 2026-01-15）
- 類型：收入、支出、轉帳（中文，對應資料庫收入/income、支出/expense、轉帳/transfer）
- 金額：整數或小數點後兩位（例如 100 或 100.50），不得為負數
- 分類：最多 50 個字元
- 記錄者：使用者名稱（選填，若不提供則使用目前登入使用者）
- 備註：選填，最多 255 個字元

### 錯誤處理
- 檔案上傳失敗時顯示友善錯誤訊息
- CSV 格式錯誤（缺少欄位、日期格式錯誤、金額格式錯誤、類型不正確）的記錄跳過並記錄錯誤原因
- 查詢失敗時不中斷頁面渲染，改寫 `error.log` 並顯示友善錯誤訊息
- 匯入失敗的記錄不寫入資料庫，但已成功匯入的記錄保留

## Acceptance Criteria

1. 存在匯入 CSV 頁面（新增 `import_csv.php` 頁面）
2. 帳本詳情頁提供「匯入 CSV」操作按鈕
3. 匯入動作具備嚴格的帳本權限驗證（透過 `ledger_access` 做 IDOR 防護）
4. 匯入動作具備嚴格的 CSRF Token 防護（表單需包含 `csrf_token` 隱藏欄位，伺服端以 `checkCsrf()` 驗證）
5. 匯入前驗證每筆記錄的格式：日期、類型、金額、分類
6. 錯誤記錄跳過並顯示錯誤原因，不影響其他記錄的匯入
7. 匯入成功後顯示結果摘要：成功筆數、失敗筆數、失敗原因
8. 金額以整數分儲存，顯示時經 `formatCents()` 格式化
9. 所有輸出經 `h()` 轉義，無 XSS 風險
10. 檔案上傳限制：僅允許 .csv 副檔名，檔案大小上限 2MB
11. 匯入動作具備嚴格的 CSRF Token 防護（表單需包含 `csrf_token` 隱藏欄位，伺服端以 `checkCsrf()` 驗證）

## Additional context

### 資料庫變更
- 無新增資料庫表，僅複用既有 `entries` 表
- 無需 migration

### 資料流（Data Flow）
1. 使用者在帳本詳情頁點擊「匯入 CSV」按鈕
2. 伺服端驗證 `ledger_id`（整數）、`ledger_access` 權限（owner/member 可匯入，viewer 僅可檢視）
3. 使用者上傳 CSV 檔案，伺服端驗證檔案類型（.csv）、大小（≤2MB）、防止路徑遍歷；表單需包含 `csrf_token` 隱藏欄位，伺服端以 `checkCsrf()` 驗證
4. 讀取 CSV 檔案內容，採用 `fgetcsv()` 逐行讀取，第一列視為標題行並跳過
5. 逐行驗證：日期格式（`isValidDate()`）、類型（收入/支出/轉帳，轉換為 income/expense/transfer）、金額格式（`toCents()`，不得為負數）、分類長度（≤50 字元）、記錄者（若不提供則使用目前登入使用者 $userId）
6. 驗證通過的記錄寫入 `entries` 表；失敗的記錄記錄錯誤原因但不寫入
7. 匯入完成後顯示結果摘要：成功筆數、失敗筆數、失敗原因
8. 匯入成功後，呼叫 `logAudit('csv_import', 'ledger_id=' . $ledgerId . ' success=' . $successCount . ' failed=' . $failedCount)` 記錄至 audit_log

### 與現有程式碼相容性
- `export_csv.php` 已實作 CSV 匯出，使用純 PHP，可參考其權限檢查與查詢模式
- 所有寫入必須用 PDO 預備陳述式、所有路徑 `./` 開頭、所有輸出 `h()` 轉義
- `add_entry.php` 已實作新增記錄，可參考其驗證邏輯（金額、類型、日期、分類長度）
- `formatCents()`、`h()`、`requireLogin()` 等現有輔助函數可直接複用，無需新增
- 不修改既有 `ledger.php`、`dashboard.php` 等頁面，僅新增 `import_csv.php` 頁面

### CSV 檔案處理
- 上傳後即時處理，不儲存在伺服器（直接由 `$_FILES['tmp_name']` 讀取）
- 僅允許 .csv 副檔名，檔案大小上限 2MB
- CSV 編碼支援 UTF-8（含 BOM 或不含 BOM 均可，BOM 會自動去除）
- 欄位順序：日期、類型、金額、分類、記錄者、備註（記錄者可選）
- 第一列為標題行，自動跳過不參與匯入

### 身分驗證與權限模型
不變更既有登入與帳本權限模型。繼續使用 session 登入與 `ledger_access` 權限檢查（owner/member 可匯入，viewer 僅可檢視，匯入為寫入操作）。

### 資料傳輸加密標準
無新增外部 API 呼叫，全部為伺服端 SQL 與 session 驗證，資料僅儲存在站台自身 SQLite 資料庫。CSV 檔案上傳後即時處理，不儲存在伺服器。

### 非功能性需求
- **效能**：CSV 匯入涉及多筆記錄寫入，但 SQLite 與 WAL 模式可接受；單一帳本查詢，效能影響可忽略
- **併發**：僅讀取查詢與單一寫入，資料庫寫入競合可接受
- **資料保留**：匯入的記錄與既有記錄同樣保留，軟刪除後不顯示但不刪除實體資料
- **可用性**：匯入失敗時顯示友善錯誤訊息，錯誤寫入 `error.log`

## 待釐清事項（非阻塞）

- 不新增匯入範本下載功能
- 不新增自動定期匯入（需排程功能，列為後續版本）
