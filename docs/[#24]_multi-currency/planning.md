## 功能描述

支援多幣別記帳，自動換算為台幣結餘。記錄時記錄原幣別與金額，結餘以設定匯率換算為台幣顯示。

## 專案函數與術語說明

- 輸出轉義函數（h()）：防護跨站腳本（XSS）的函數，所有使用者可控輸出皆經此函式。
- 跨站請求偽造（CSRF）：防護網頁請求被偽造的機制。
- PHP 資料物件（PDO）：用於資料庫查詢的預備陳述式介面，選用理由為符合專案「純 PHP + PDO 預備陳述式」技術約束，防止 SQL 注入。
- 應用程式介面（API）：軟體元件間溝通的介面規格。
- 角色存取控制（RBAC）：根據使用者角色控管存取權限的模型。
- 預寫日誌（WAL）：SQLite 資料庫日誌模式，支援多讀寫併發，選用理由為 SQLite 在多併發讀寫場景下可避免鎖定失敗，符合共享主機環境需求。
- 超文字傳輸協定（HTTP）：網頁請求與回應傳輸協定。
- 工作階段（session）：伺服端儲存使用者登入狀態的機制。
- 國際貨幣代碼標準（ISO 4217）：國際標準化組織制定的貨幣三字母代碼標準（如 TWD、USD、JPY、CNY；參見 https://www.iso.org/iso-4217-currency-codes.html）。
- 登入保護機制（requireLogin()）：檢查 $_SESSION['user_id'] 是否存在，未登入導向登入頁。
- 帳本存取權限表（ledger_access）：記錄使用者對各帳本的角色（擁有者（owner）/成員（member）/檢視者（viewer））。
- 稽核記錄表（audit_log）：記錄誰在何時做了什麼操作，僅新增不刪除。
- 分類支出明細表（entries）：儲存所有記帳記錄的資料表，欄位包括記錄編號、帳本編號、使用者編號、金額（整數分）、類型、類別、記錄日期、備註。
- 換算後金額整數分（amount_cents）：entries 表欄位，業務意義為匯率換算後的台幣金額，以整數分儲存。
- 私密資料庫目錄（private_data/）：專案用於儲存錯誤日誌等非公開資料的私密目錄，錯誤詳情寫入 private_data/error.log，不公開下載。

## 使用者故事

作為有海外消費或海外收入的家庭成員，我想記錄外幣金額，系統自動換算為台幣，方便總覽家庭收支。

## 預期行為

1. entries 資料表新增欄位：原幣別（currency，預設 TWD）、匯率（exchange_rate，相對於 TWD）。
2. 新增記錄時可選擇幣別（TWD/USD/JPY/CNY 等），輸入原幣金額。
3. 系統以匯率換算為台幣金額（amount_cents 儲存台幣整數分），原幣金額與幣別保留供查詢。
4. 匯率可手動設定（本期）。
5. 導出報表時顯示原幣金額與台幣換算金額。
6. 金額以整數分儲存（台幣），顯示除以 100。
7. 所有輸出經 h() 轉義。
8. SQL 查詢使用 PDO 預備陳述式，具名佔位符。
9. 權限檢查：使用者對該帳本有帳本存取權限表（ledger_access）。

## 資料流

使用者於新增記錄頁面選擇幣別並輸入原幣金額與匯率；伺服端驗證登入階段（requireLogin）與帳本存取權限（ledger_access）；以匯率換算為台幣金額，amount_cents 儲存台幣整數分，原幣金額與幣別保留於新欄位；以 PDO 預備陳述式 INSERT 入 entries 表；導出報表時顯示原幣金額與台幣換算金額；所有輸出經 h() 轉義。登入失敗時拒絕請求；權限不足時顯示錯誤訊息；資料庫寫入失敗時顯示通用錯誤頁並記錄至 private_data/error.log。

```mermaid
flowchart TD
    A[使用者選擇幣別輸入原幣金額與匯率] --> B{登入驗證通過？}
    B -->|否| C[拒絕請求]
    B -->|是| D[ledger_access 權限檢查]
    D -->|否| E[顯示權限不足錯誤]
    D -->|是| F[以匯率換算為台幣整數分 amount_cents]
    F --> G{資料庫寫入成功？}
    G -->|否| H[顯示通用錯誤頁並記錄至 error.log]
    G -->|是| I[導出報表顯示原幣與台幣兩欄 h() 轉義]
```

## 業務驗收條件

- 外幣記帳頁面（./multi_currency.php）可供使用者存取。
- 新增記錄頁面新增幣別下拉選單（預設 TWD）與匯率輸入欄。
- amount_cents 儲存換算後的台幣整數分，原幣金額儲存於新欄位，匯率換算後的金額與原幣金額相符（以匯率乘數驗證）。
- 導出報表顯示原幣與台幣兩欄。
- 整數分四捨五入規則：匯率換算後的台幣金額以整數分（1 分）四捨五入，採四捨五入（0.5 分向上進位）儲存於 amount_cents；金額顯示時除以 100 並保留兩位小數。
- 所有輸出經輸出轉義函數（h()）轉義。

## 錯誤處理與邊界條件

- 匯率輸入錯誤（非數字、負數）：顯示錯誤訊息，不寫入資料庫，HTTP 回應 400。
- 幣別不支援：顯示錯誤訊息，下拉選單僅顯示支援幣別。
- 換算溢位/四捨五入邊界：整數分四捨五入規則依開發者確認後實作（待開發者決定事項），顯示兩位小數。
- 資料庫寫入失敗：顯示通用錯誤頁，詳細錯誤寫入 ./private_data/error.log。
- SQLite 鎖定/斷線：顯示通用錯誤頁，詳細錯誤寫入 ./private_data/error.log。

## 身分驗證與權限控管

- 身分驗證：依賴既有 session 登入機制，requireLogin() 檢查 $_SESSION['user_id']，未登入導向 login.php。
- 權限控管：使用帳本存取權限表 ledger_access，角色分為擁有者（owner）、成員（member）、檢視者（viewer），僅擁有者與成員可新增外幣記錄。
- 資料傳輸加密：依賴既有 HTTPS Session Cookie 設定（secure、HttpOnly、SameSite=Lax）。
- 跨站請求偽造（CSRF）權杖防護：新增外幣記帳表單需含 CSRF 權杖，以 hash_equals() 驗證，符合專案技術約束。

## 非本期範圍

- 自動匯率抓取：本期匯率為手動輸入，不自動從外部 API 抓取。
- 多幣別預算：本期不支援多幣別預算設定。
- 匯率歷史紀錄：本期不保留匯率變更歷史。

## 非功能性需求

- 預期效能：外幣記帳頁面載入時間，具體數值待效能測試後確認。
- 併發處理量：單筆 INSERT 操作，SQLite WAL 模式支援多併發。
- 資料保留策略：currency 與 exchange_rate 欄位隨 entries 記錄生命週期保留。
- 系統可用性：匯率換算失敗不影響台幣記帳功能。

## 待開發者決定的事項

- 換算精度：整數分四捨五入規則。
