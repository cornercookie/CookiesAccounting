## Description

為「全家人記帳系統」新增「年度／季度報表」功能，讓使用者能跨多個月份查看收支彙總，適合季度對帳、年度總結等場景。使用者可選擇特定年份（年度報表）或特定年份的季度（季度報表），系統顯示該期間內的收入、支出、轉帳、結餘總額，並可分帳本查看。

範圍限於單一帳本的年度/季度彙總；不新增資料庫表，僅複用既有 `entries` 表；不支援多帳本合併報表（列為後續版本）。

## User Story

- 作為家長，我希望能看到今年全年的收支總結，了解全年開銷情況，方便明年預算規劃。
- 作為家庭成員，我希望能查看特定季度的收支，例如第三季度的旅遊開銷，了解特定期間的花費分佈。

## To Reproduce

本項目非錯誤（bug）類需求，不適用重現步驟。

## Expected behavior

### 年度報表
- 使用者可選擇特定年份（例如 2026 年），系統顯示該年份內所有月份的收支彙總，以及全年總收入、總支出、總轉帳、總結餘。
- 若該年份無任何記錄，顯示「該年度無記錄」文字提示。

### 季度報表
- 使用者可選擇特定年份與季度（Q1/Q2/Q3/Q4），系統顯示該季度內三個月的收支彙總，以及季度總收入、總支出、總轉帳、總結餘。
- 季度對應月份：Q1 = 1-3 月，Q2 = 4-6 月，Q3 = 7-9 月，Q4 = 10-12 月。

### 欄位與格式
- 金額皆經 `formatCents()` 格式化（整數分除以 100、千分位顯示），不使用 FLOAT。
- 所有輸出經 `h()` 轉義。
- 類別統計可選擇顯示該期間內各類別支出佔比（與現有 ledger.php 類別統計圖表邏輯類似，但時間範圍擴大至季度/年度）。

### 權限檢查
- 所有查詢皆透過 `ledger_access` 做 IDOR 防護，使用者只能查看其被授權帳本的報表。
- viewer 僅可檢視，owner/member 可檢視（查詢為唯讀，不涉及寫入）。

### 錯誤處理
- 查詢失敗時不中斷頁面渲染，改寫 `error.log` 並顯示已取得的資料（若有）或友善錯誤訊息。
- 無記錄時顯示「該期間無記錄」文字提示，而非空白頁面。
- 年份/季度/帳本 ID 參數不合法時，顯示友善錯誤訊息或回退至預設值（當年當季）。

## Acceptance Criteria

1. 存在年度報表頁面，使用者可選擇年份，顯示該年度內各月份及全年總收支。
2. 存在季度報表頁面，使用者可選擇年份與季度（Q1-Q4），顯示該季度內各月份及季度總收支。
3. 年度/季度報表的收入、支出、轉帳、結餘金額皆經 `formatCents()` 格式化（整數分除以 100、千分位顯示）。
4. 所有輸出經 `h()` 轉義，無 XSS 風險。
5. 所有查詢皆透過 `ledger_access` 做 IDOR 防護，使用者只能查看其被授權帳本的報表。
6. 無記錄時顯示「該期間無記錄」文字提示，而非空白頁面。
7. 查詢失敗時不中斷頁面渲染，錯誤寫入 `error.log`。
8. 與現有月度報表（ledger.php）功能並存，不破壞既有功能。

## Additional context

### 資料庫變更
- 無新增資料庫表，僅複用既有 `entries` 表。
- 無需 migration。

### 資料流（Data Flow）
1. 使用者在報表頁面選擇報表類型（年度/季度）、年份、季度（若為季度報表），經 `ledger_id` 指定帳本。
2. 伺服端驗證輸入參數：
   - `ledger_id`：必須為整數，且使用者必須透過 `ledger_access` 擁有該帳本的存取權（owner/member/viewer 均可檢視）。
   - `year`：必須為 4 位整數（例如 2026），格式不符時顯示錯誤訊息或回退至當年。
   - `quarter`（季度報表專用）：必須為 Q1-Q4 或 1-4，格式不符時顯示錯誤訊息或回退至當季。
3. 根據年份/季度計算起始與結束日期（Asia/Taipei 時區），使用 `new DateTimeImmutable('now', new DateTimeZone('Asia/Taipei'))` 取得當前日期，以 `Y-m-d` 格式與 `entries.entry_date` 比較。
4. 查詢 `entries` 表，加入 `INNER JOIN ledger_access la ON la.ledger_id = e.ledger_id AND la.user_id = :user_id` 做 IDOR 權限裁切，再加上 `WHERE e.ledger_id = :ledger_id AND e.deleted = 0 AND e.entry_date BETWEEN :startDate AND :endDate`。
5. GROUP BY 類型（income/expense/transfer）計算各類總額，GROUP BY 月份計算各月份彙總。
6. 金額經 `formatCents()` 格式化後輸出，所有文字經 `h()` 轉義。
7. 若無記錄，顯示「該期間無記錄」。

### 與現有程式碼相容性
- `ledger.php` 已有月度查詢邏輯（`$ym` 參數、`Y-m` 格式、`INNER JOIN ledger_access` 權限裁切），年度/季度報表可複用相同的查詢模式，僅擴大日期範圍。
- `formatCents()`、`h()`、`requireLogin()` 等現有輔助函數可直接複用，無需新增。
- 不修改既有 `ledger.php`、`dashboard.php` 等頁面，僅新增報表頁面（可放在根目錄或 `reports/` 子目錄，視專案結構決定）。

### 身分驗證與權限模型
不變更既有登入與帳本權限模型。繼續使用 session 登入與 `ledger_access` 權限檢查（owner/member/viewer 均可檢視報表，因為僅為唯讀查詢）。

### 資料傳輸加密標準
無新增外部 API 呼叫，全部為伺服端 SQL 與 session 驗證，資料僅儲存在站台自身 SQLite 資料庫。

### 非功能性需求
- **效能**：年度/季度查詢涉及較多記錄，但 SQLite 與 WAL 模式可接受；單一帳本查詢，效能影響可忽略。
- **併發**：僅讀取查詢，無資料庫寫入競合。
- **資料保留**：不涉及資料寫入，無資料保留問題。
- **可用性**：查詢失敗時不中斷頁面渲染，錯誤寫入 `error.log`。

### CSRF 說明
本頁面為唯讀 GET 查詢，無狀態改寫表單，不產生也不驗證 CSRF Token。

### 差異與待確認
- 年度報表頁面路徑：可放在根目錄（如 `yearly_report.php`）或 `reports/` 子目錄，視專案結構決定，於 Design.md 階段釐清。
- 季度報表與年度報表是否合併為同一頁面（透過參數區分）或分為兩頁：於 Design.md 階段釐清。

### 非本期範圍（Out of Scope）
- 不新增多帳本合併報表（每次僅查看單一帳本）。
- 不新增圖表匯出（PDF/Excel）、不新增自動推播通知。
- 不新增預算對比（年度預算設定列為後續版本）。
- 不新增多年度比較圖表。
