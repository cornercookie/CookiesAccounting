## 功能描述

上傳或輸入統一發票號碼，自動對中獎號碼，中獎金額記為收入。針對台灣家庭場景的在地化功能。

## 專案函數與術語說明

- 統一發票：臺灣常用業務術語，指臺灣財政部發行之統一發票，無通用英文縮寫，採中文業務名稱。
- 輸出轉義函數（h()）：用於防護跨站腳本（XSS）。
- 跨站請求偽造（CSRF）：防護網頁請求被偽造的機制。
- PHP 資料物件（PDO）：用於資料庫查詢的預備陳述式介面，選用理由為符合專案「純 PHP + PDO 預備陳述式」技術約束，防止 SQL 注入。
- 預寫日誌（WAL）：SQLite 資料庫日誌模式，支援多讀寫併發，選用理由為 SQLite 在多併發讀寫場景下可避免鎖定失敗，符合共享主機環境需求。
- 超文字傳輸協定（HTTP）：網頁請求與回應傳輸協定。
- 角色存取控制（RBAC）：根據使用者角色控管存取權限的模型。
- 分錄記錄表（entries）：儲存所有記帳記錄（收入、支出、轉帳）。
- 記錄類型欄位（type）：業務意義為收入（income）、支出（expense）或轉帳（transfer）。
- 分類欄位（category）：業務意義為記帳項目的分類名稱。
- 帳本存取權限表（ledger_access）：記錄使用者對各帳本的角色（擁有者（owner）/成員（member）/檢視者（viewer））。
- 稽核記錄表（audit_log）：記錄誰在何時做了什麼操作，僅新增不刪除。
- 登入保護機制（requireLogin()）：檢查 $_SESSION['user_id']，未登入導向登入頁。
- 對獎查詢動作（invoice_lottery_check）：audit_log 記錄使用者對發票號碼進行對獎比對的動作。
- 記帳建立動作（entry_create）：audit_log 記錄使用者將中獎金額記為收入並新增 entries 記錄的動作。

## 使用者故事

作為台灣家庭成員，我想輸入統一發票號碼，系統自動幫我對獎，中獎金額自動記為收入。

## 預期行為

1. 新增發票對獎頁面，輸入發票號碼（8 碼）與對獎期別。
2. 系統比對當期中獎號碼（特別獎、特獎、頭獎、二獎至六獎，中獎號碼由使用者手動輸入）。
3. 比對發票號碼，顯示中獎結果與金額。
4. 中獎金額可一鍵記為該帳本收入（新增 entries 記錄，類型 type=income，分類 category=發票中獎）。
5. 稽核記錄表（audit_log）記錄對獎動作與記帳動作，action 為 invoice_lottery_check 與 entry_create。
6. 金額以整數分儲存，顯示除以 100。
7. 所有輸出經 h() 轉義。
8. SQL 查詢使用 PDO 預備陳述式，具名佔位符。
9. 權限檢查：使用者對該帳本有帳本存取權限表（ledger_access）（擁有者/member 可記帳，檢視者僅可查詢）。

## 資料流（Data Flow）

使用者於發票對獎頁面輸入發票號碼（8 碼）與對獎期別；伺服端驗證發票號碼格式（8 碼數字）；比對手動輸入的中獎號碼（特別獎、特獎、頭獎、二獎至六獎）；顯示中獎結果與金額；使用者一鍵記為收入時，以 PDO 預備陳述式 INSERT 入 entries 表（type=income, category=發票中獎，金額以整數分儲存）；寫入 audit_log（action=invoice_lottery_check 與 entry_create）；所有輸出經 h() 轉義。

## 業務驗收條件

- 發票對獎頁面（./invoice_lottery.php）可供使用者存取。
- 未登入使用者導向登入頁。
- 發票號碼輸入驗證（8 碼數字），格式錯誤不執行對獎。
- 中獎號碼比對邏輯（特別獎、特獎、頭獎、二獎至六獎）。
- 中獎金額記為收入表單（含 CSRF 權杖），CSRF 權杖驗證失敗拒絕請求。
- 擁有者與成員可將中獎金額記為收入，檢視者僅可查詢對獎結果。
- 金額以整數分儲存，顯示時除以 100。
- audit_log 記錄對獎動作與記帳動作。
- 所有使用者可控輸出經輸出轉義函數（h()）轉義。

## 錯誤處理與邊界條件

- 發票號碼格式錯誤（非 8 碼數字）：顯示錯誤訊息，不執行對獎，HTTP 回應 400。
- 對獎期別不存在：顯示「找不到該期別中獎號碼」。
- 中獎號碼資料庫為空：顯示「尚未設定該期別中獎號碼，請先手動輸入」。
- 資料庫寫入失敗：顯示通用錯誤頁，詳細錯誤寫入 private_data/error.log。
- CSRF 權杖驗證失敗：拒絕請求，顯示通用錯誤訊息。

## 身分驗證與權限控管

- 身分驗證：依賴既有 session 登入機制，requireLogin() 檢查 $_SESSION['user_id']，未登入導向 login.php。
- 權限控管：使用帳本存取權限表 ledger_access，角色分為擁有者（owner）、成員（member）、檢視者（viewer），擁有者與成員可記帳，檢視者僅可查詢對獎結果。
- 資料傳輸加密：依賴既有 HTTPS Session Cookie 設定（secure、HttpOnly、SameSite=Lax）。
- 跨站請求偽造（CSRF）權杖防護：中獎金額記為收入表單需含 CSRF 權杖，以 hash_equals() 驗證。

## 非本期範圍（Out of Scope）

- 自動抓取中獎號碼：本期中獎號碼為手動輸入，不自動從政府發票對獎公開管道抓取。
- 發票圖片掃描：本期僅支援號碼手動輸入，不支援發票圖片掃描辨識。
- 中獎通知：本期不自動發送中獎通知。

## 非功能性需求

- 預期效能：對獎比對回應時間不超過 2 秒。
- 併發處理量：單筆對獎與記帳操作，SQLite WAL 模式支援多併發。
- 資料保留策略：audit_log 儲存期限依現有規則，未知值列為待確認，不捏造。
- 系統可用性：對獎失敗不影響其他帳本功能。
