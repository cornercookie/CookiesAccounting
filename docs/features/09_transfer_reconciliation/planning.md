## 功能描述

當一筆「轉帳」記錄在 A 帳本支出、B 帳本收入時，可將兩筆關聯，顯示對帳狀態（已配對/未配對），解決跨帳本轉帳難對帳問題。

## 專案函數與術語說明

- 輸出轉義函數（h()）：用於防護跨站腳本（XSS）。
- 跨站請求偽造（CSRF）：防護網頁請求被偽造的機制。
- PHP 資料物件（PDO）：用於資料庫查詢的預備陳述式介面，選用理由為符合專案「純 PHP + PDO 預備陳述式」技術約束，防止 SQL 注入。
- 登入保護機制（requireLogin()）：檢查 $_SESSION['user_id']，未登入導向登入頁。
- 帳本存取權限表（ledger_access）：記錄使用者對各帳本的角色（擁有者（owner）/成員（member）/檢視者（viewer））。
- 稽查記錄表（audit_log）：記錄誰在何時做了什麼操作，僅新增不刪除。
- 預寫日誌（WAL）：SQLite 資料庫日誌模式，支援多讀寫併發，選用理由為 SQLite 在多併發讀寫場景下可避免鎖定失敗，符合共享主機環境需求。

## 使用者故事

作為家庭成員，我想將跨帳本的轉帳記錄配對（例如爸爸帳本支出、媽媽帳本收入），清楚知道哪些轉帳尚未對齊。

## 預期行為

1. entries 資料表新增欄位 transfer_pair_id（自參考，可為 NULL），兩筆轉帳互為對應。
2. 儀表板或 ledger.php 顯示未配對轉帳清單（轉帳類型且 transfer_pair_id 為 NULL）。
3. 使用者可選擇兩筆轉帳記錄進行配對（POST 表單，含 CSRF 權杖）。
4. 配對後兩筆記錄的 transfer_pair_id 互為對方 id，狀態顯示「已配對」。
5. 稽查記錄表（audit_log）記錄配對動作，action 為 transfer_pair。
6. 所有輸出經 h() 轉義。
7. SQL 查詢使用 PDO 預備陳述式，具名佔位符。
8. 權限檢查：使用者對兩筆記錄所屬帳本皆有 ledger_access。
9. 轉帳金額不必相等（可記錄手續費或誤差），配對時顯示差額。

## 資料流（Data Flow）

使用者於轉帳配對頁面選擇兩筆轉帳記錄，以 POST 提交含 CSRF 權杖的表單；伺服端驗證登入階段（requireLogin）與兩筆記錄所屬帳本的 ledger_access 權限；檢查兩筆記錄皆為轉帳類型且 transfer_pair_id 為 NULL；以 PDO 預備陳述式 UPDATE 兩筆 entries 設定 transfer_pair_id 互為對方 id；寫入 audit_log 記錄配對動作；所有輸出經 h() 轉義；金額以整數分儲存，差額顯示時除以 100。

```mermaid
flowchart TD
    A[使用者選擇兩筆轉帳記錄] --> B[POST 表單含 CSRF 權杖]
    B --> C[requireLogin 驗證登入]
    C --> D[兩筆記錄所屬帳本 ledger_access 權限檢查]
    D --> E[檢查兩筆皆為轉帳且 transfer_pair_id 為 NULL]
    E --> F[PDO UPDATE 兩筆 entries 設定 transfer_pair_id 互為對方 id]
    F --> G[audit_log 記錄 transfer_pair]
    G --> H[未配對清單更新 h() 轉義顯示]
```

## 業務驗收條件

- 轉帳配對頁面（./transfer_pair.php）可供使用者存取。
- 轉帳清單頁面顯示未配對轉帳（轉帳類型且 transfer_pair_id 為 NULL），依帳本分組。
- 配對表單提交時，系統驗證跨站請求偽造（CSRF）權杖，驗證失敗拒絕請求。
- 配對成功後，兩筆轉帳記錄的 transfer_pair_id 互為對方 id，狀態顯示「已配對」。
- 轉帳金額不等時，配對時顯示差額（金額以整數分儲存，顯示時除以 100）。
- 稽查記錄表記錄配對動作（action=transfer_pair）。
- 所有使用者可控輸出經輸出轉義函數（h()）轉義。

## 錯誤處理與邊界條件

- 兩筆記錄不屬於同一使用者可存取的帳本：拒絕配對，顯示「您沒有這兩筆記錄的存取權限」，HTTP 回應 403。
- 記錄不存在或非轉帳類型：顯示「找不到對應的轉帳記錄」。
- 記錄已配對（transfer_pair_id 不為 NULL）：顯示「該記錄已配對，不可重複配對」。
- CSRF 權杖驗證失敗：拒絕請求，顯示通用錯誤訊息。
- 資料庫寫入失敗：顯示通用錯誤頁，詳細錯誤寫入 private_data/error.log。
- 轉帳金額不等：不阻止配對，顯示差額（金額以整數分儲存，顯示時除以 100）。

## 身分驗證與權限控管

- 身分驗證：依賴既有 session 登入機制，requireLogin() 檢查 $_SESSION['user_id']，未登入導向 login.php。
- 權限控管：使用帳本存取權限表 ledger_access，角色分為擁有者（owner）、成員（member）、檢視者（viewer），使用者對兩筆記錄所屬帳本皆需有存取權限。
- 資料傳輸加密：依賴既有 HTTPS Session Cookie 設定（secure、HttpOnly、SameSite=Lax）。

## 非本期範圍（Out of Scope）

- 自動配對規則：本期僅支援手動選擇兩筆記錄配對，不支援自動比對規則。
- 轉帳提醒：本期不自動提醒未配對轉帳。
- 跨帳本餘額檢視：本期不支援跨帳本餘額總覽檢視。

## 非功能性需求

- 預期效能：配對動作為雙筆更新，回應時間不超過 2 秒。
- 併發處理量：單筆配對操作，SQLite WAL 模式支援多併發。
- 資料保留策略：transfer_pair_id 隨 entries 記錄生命週期保留，不額外歸檔。
- 系統可用性：配對失敗時顯示錯誤訊息，不影響轉帳清單檢視。
