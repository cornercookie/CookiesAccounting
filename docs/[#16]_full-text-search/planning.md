## 功能描述

建立全站記錄搜尋功能，讓使用者可依關鍵字（類別、備註、成員）、金額範圍、日期範圍，在有存取權限的帳本中搜尋記帳記錄。結果以分頁顯示，所有輸出經輸出轉義函式（h()）轉義，查詢採用 PHP 資料物件（PDO）預備陳述式。

## 使用者故事

作為家庭成員，我想在所有可存取的帳本中搜尋特定記錄，例如「上個月大約 3000 元的餐費」，而不需要逐本翻月份查找。

## 重現步驟

不適用（非 bug 類功能）。

## 預期行為

1. 使用者進入搜尋頁面，可輸入關鍵字、金額下限/上限、起始/結束日期。
2. 僅搜尋使用者有帳本存取權限表（ledger_access）權限的帳本（擁有者（owner）/成員（member）/檢視者（viewer）皆可搜尋，檢視者僅檢視）。
3. 結果依記帳日期（entry_date）降冪排列，每頁 50 筆，支援分頁。
4. 搜尋條件為空時，回傳該使用者所有可存取帳本的最近 50 筆記錄。
5. 金額欄位以整數分儲存，查詢時以金額轉整數分函式（toCents()） 解析，避免浮點數（FLOAT）。
6. 所有使用者可控輸出（關鍵字、類別、備註）經 h() 轉義防護跨站腳本（XSS）。
7. 搜尋表單含跨站請求偽造（CSRF）權杖，POST 時以 hash_equals() 驗證。
8. 無符合結果時顯示「沒有符合篩選條件的記錄」。

## 專案函數與術語說明

- 超文字標記語言（HTML）輸出轉義函式（h()）：用於防護跨站腳本（XSS），所有使用者可控輸出皆經此函式。
- 金額轉整數分函式（toCents()）：將「元」字串解析為整數分，避免浮點數誤差。
- 日期格式驗證函式（isValidDate()）：確認輸入為合法 Y-m-d 曆日。
- 登入保護機制（requireLogin()）：檢查 $_SESSION['user_id']，未登入導向登入頁。
- 帳本存取權限表（ledger_access）：記錄使用者對各帳本的角色（擁有者（owner）/成員（member）/檢視者（viewer））。
- 稽查記錄表（audit_log）：記錄誰在何時做了什麼操作，僅新增不刪除。
- 結構化查詢語言（SQL）查詢：使用 PDO 預備陳述式查詢資料庫，不拼字串。
- 記帳記錄表（entries）：儲存所有記帳分類支出記錄的資料表，包含類別、金額、日期等欄位。
- 記帳日期（entry_date）：entries 表欄位，業務意義為該筆記帳發生的日期。
- 金額整數分（amount_cents）：entries 表欄位，業務意義為該筆記帳的金額，以整數分儲存，避免浮點數誤差。
- 使用者 ID（user_id）：entries 表欄位，業務意義為記帳記錄的建立者使用者識別碼。
- 超文字傳輸協定（HTTP）：網頁請求與回應傳輸協定。
- 預寫日誌（WAL）：SQLite 資料庫日誌模式，支援多讀寫併發，選用理由為 SQLite 在多併發讀寫場景下可避免鎖定失敗，符合共享主機環境需求。

## 資料流（Data Flow）

使用者於搜尋頁面輸入關鍵字、金額範圍、日期範圍，以 POST 提交含 CSRF 權杖的表單；伺服端驗證登入階段（requireLogin）與帳本存取權限（ledger_access）；以 結構化查詢語言（SQL）預備陳述式查詢 entries 表，以 金額轉整數分函式（toCents()）解析金額、以 日期格式驗證函式（isValidDate()）驗證日期；結果依 entry_date 降冪排列、分頁後以 超文字標記語言（HTML）輸出轉義函式（h()）轉義輸出；搜尋動作寫入稽查記錄表（audit_log），action 為 entry_search。參數驗證失敗時回傳 400，資料庫連線失敗時顯示通用錯誤頁並記錄至 error.log。

```mermaid
flowchart TD
    A[使用者輸入搜尋條件] --> B[POST 表單含 CSRF 權杖]
    B --> C[requireLogin 驗證登入]
    C --> D[ledger_access 權限檢查]
    D --> E{參數驗證通過？}
    E -->|否| F[回傳 400 錯誤]
    E -->|是| G[PDO 預備陳述式查詢 entries]
    G --> H{資料庫連線正常？}
    H -->|否| I[顯示通用錯誤頁]
    H -->|是| J[toCents/isValidDate 驗證參數]
    J --> K[分頁與 h() 轉義輸出]
    K --> L[audit_log 記錄 entry_search]
```

## 業務驗收條件

- 新增 `docs/features/01_full_text_search/search.php` 搜尋頁面。
- 頁面以登入保護機制 requireLogin() 保護，未登入導向登入頁。
- SQL 查詢全程使用 PDO 預備陳述式，具名佔位符，不拼字串。
- 權限檢查：INNER JOIN ledger_access 與 la.user_id = :user_id，未授權帳本不出現。
- 支援關鍵字 LIKE 搜尋（%、_、\ 已逃脫）。
- 支援金額範圍（amount_cents BETWEEN），輸入經 toCents() 驗證。
- 支援日期範圍（entry_date BETWEEN），輸入經日期格式驗證函式 isValidDate() 驗證。
- 分頁每頁 50 筆，頁碼超出範圍自動修正。
- 所有輸出經 h() 轉義，錯誤訊息不外洩 SQL 路徑或堆疊。
- 搜尋動作寫入 audit_log，action 為 entry_search。

## 錯誤處理與邊界條件

- 輸入格式錯誤（金額非數字、日期格式不正確）：顯示錯誤訊息，不執行查詢，超文字傳輸協定（HTTP）回應 400。
- CSRF 權杖驗證失敗：拒絕請求，顯示通用錯誤訊息，不外洩系統內部資訊。
- 資料庫連線失敗或查詢逾時：顯示通用錯誤頁，詳細錯誤寫入 private_data/error.log，不外洩堆疊。
- 分頁參數無效（負數、超過總頁數）：自動修正為第 1 頁或最後一頁。
- 無符合結果：顯示「沒有符合篩選條件的記錄」，非錯誤狀態。

## 身分驗證與權限控管

- 身分驗證：依賴既有 session 登入機制，requireLogin() 檢查 $_SESSION['user_id']，未登入導向 login.php。
- 權限控管：使用帳本存取權限表 ledger_access，角色分為擁有者（owner）、成員（member）、檢視者（viewer），三者皆可搜尋，檢視者僅可檢視結果，不可進行狀態變更。
- 資料傳輸加密：依賴既有超文字傳輸協定安全版（HTTPS）會話 Cookie（Session Cookie）設定（secure 僅安全連線傳送、HttpOnly 僅伺服端可存取、SameSite=Lax 跨站請求限制）。

## 非本期範圍（Out of Scope）

- 全文索引（FTS）：本期採用 LIKE 查詢，不引入 FTS 擴充。
- 搜尋歷史紀錄：不儲存使用者搜尋條件歷史。
- 儲存搜尋條件：不提供搜尋條件儲存與重複使用功能。

## 非功能性需求

- 預期效能：單次搜尋回應時間在目標主機環境上不超過 3 秒（資料量未過萬筆時，數值待開發者確認）。
- 併發處理量：SQLite 預寫日誌（WAL）模式支援多讀寫併發，搜尋為唯讀查詢，不阻塞寫入。
- 資料保留策略：搜尋不產生額外資料，僅寫入 audit_log，保留期間依現有 audit_log 規則。
- 系統可用性：搜尋頁面為唯讀，資料庫暫時鎖定時可重試或顯示稍後再試。

## 待開發者決定的事項
